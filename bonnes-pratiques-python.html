Mauvais vs Bon

Nommage clair et explicite
Lisibilité
❌ Mauvais
def calc(x, y):
    return x * 0.20 + y
✅ Bon
def calculer_prix_ttc(prix_ht, taux_tva=0.20):
    """Retourne le prix TTC à partir du HT et du taux de TVA."""
    return prix_ht * taux_tva + prix_ht

Les noms explicites + docstring rendent le code auto-documenté.

Éviter les types non annotés
Typage statique
❌ Mauvais
def moyenne(notes):
    return sum(notes) / len(notes)
✅ Bon
from statistics import fmean

def moyenne(notes: list[float]) -> float:
    """Calcule la moyenne arithmétique des notes."""
    if not notes:
        raise ValueError("La liste ne peut pas être vide")
    return fmean(notes)

Les annotations aident les IDE, mypy et vos collègues.

Gestion des erreurs : pas d'except nu
Robustesse
❌ Mauvais
try:
    data = json.loads(raw)
except:
    pass  # avale TOUTES les erreurs, même le Ctrl+C !
✅ Bon
try:
    data = json.loads(raw)
except json.JSONDecodeError as exc:
    logger("JSON invalide: %s", exc)
    raise

Attrapez des exceptions précises, loggez, et ne masquez jamais silencieusement.

Compréhensions de liste vs boucle manuelle
Pythonic
❌ Mauvais
resultat = []
for nom in noms:
    if nom:
        resultat.append(nom.strip().lower())
✅ Bon
resultat = [nom.strip().lower()
            for nom in noms
            if nom]

Plus concis et souvent plus rapide. Générateurs ((x for x in ...)) pour les gros volumes.

Éviter les valeurs magiques et les globals
Maintenabilité
❌ Mauvais
total = prix * 1.20  # 1.20 ? pourquoi ?
compteur = 0  # variable globale modifiée partout
✅ Bon
TAUX_TVA = 0.20  # constante nommée

def calculer_total(prix: float) -> float:
    return prix * (1 + TAUX_TVA)

Constantes en MAJUSCULES, fonctions pures sans état global.

Comparaisons et vérité Pythoniques
Idiomes
❌ Mauvais
if len(ma_liste) > 0: ...
if est_actif == True: ...
if x != None: ...
✅ Bon
if ma_liste: ...
if est_actif: ...
if x is not None: ...

Une liste vide est « fausse » ; None se compare avec is (identité).

PEP 8 — Les règles essentielles

La PEP 8 est le guide de style officiel de Python. Les points à retenir :

🔤 Nommage

  • Variables / fonctions : snake_case — ma_fonction()
  • Classes : PascalCase — class GestionnaireUtilisateur:
  • Constantes : MAJUSCULES — VITESSE_MAX = 300
  • Privé (convention) : préfixe underscore — _interne, __tres_prive

📐 Espaces et mise en page

  • Indentation : 4 espaces, jamais de tabulation mélangée
  • Longueur de ligne : 79 caractères max (souvent 88–100 par convention d'équipe)
  • Deux lignes vides autour des définitions de fonctions / classes de haut niveau
  • Espaces autour des opérateurs : x = a + b, mais pas dans les mots-clés d'arguments : f(x=1)

📦 Imports

  • Un import par ligne, en haut du fichier
  • Ordre : stdlib → tierce partie → local, séparés par une ligne vide
  • Éviter from module import * (pollue l'espace de noms)

💬 Documentation

  • Docstring pour chaque module, classe et fonction publique (PEP 257)
  • Préférer les docstrings au commentaires qui expliquent le « quoi » ; les commentaires expliquent le « pourquoi »

Structure de projet & outillage

Au-delà du style, un projet Python sain repose sur une structure claire et des outils automatisés.

🗂️ Arborescence recommandée

mon_projet/
├── pyproject.toml      # configuration centrale (dépendances, outils)
├── README.md
├── src/
│   └── mon_projet/
│       ├── __init__.py
│       └── core.py
├── tests/
│   └── test_core.py
└── .gitignore

🔧 La chaîne d'outils moderne

  • Gestion des dépendances : uv ou poetry — environnements virtuels et lockfile
  • Formatage : ruff format ou black — un style uniforme, zéro débat
  • Lint : ruff check ou flake8 — détecte les pièges classiques
  • Typage : mypy ou pyright — vérifie les annotations
  • Tests : pytest — simple, lisible, avec fixtures
  • Hooks git : pre-commit — tout vérifie automatiquement à chaque commit

🧪 Un bon test avec pytest

import pytest
from mon_projet.core import moyenne

def test_moyenne_simple():
    assert moyenne([10, 20]) == 15

def test_moyenne_vide():
    with pytest.raises(ValueError):
        moyenne([])

Un test par comportement, des noms explicites, on teste aussi les cas limites.

🧠 Le Zen de Python (PEP 20)

Tapez import this dans un interpréteur… Quelques maximes :

  • « Readability counts. » — la lisibilité compte
  • « Explicit is better than implicit. » — l'explicite vaut mieux que l'implicite
  • « Simple is better than complex. » — le simple vaut mieux que le complexe
  • « Errors should never pass silently. » — les erreurs ne doivent jamais passer en silence
