Une requête dans une requête

Une sous-requête (ou requête imbriquée) est une requête SQL placée à l'intérieur d'une autre requête, entre parenthèses. Son résultat est utilisé par la requête principale.

🧠 L'analogie du détective

Pour trouver « les clients qui ont dépensé plus de 500 € », le détective procède en deux temps :

  • Étape 1 (la sous-requête) : « Trouve-moi le total des achats de chaque client »
  • Étape 2 (la requête principale) : « Parmi ces résultats, garde ceux qui dépassent 500 € »

SQL peut faire les deux en une seule commande : la sous-requête s'exécute d'abord, son résultat nourrit la requête principale.

👀 À quoi ça ressemble ?

-- La sous-requête (en vert) est TOUJOURS entre parenthèses
SELECT nom
FROM clients
WHERE id IN (SELECT client_id FROM commandes WHERE total > 500);

-- 👆 La requête principale  👆 La sous-requête, exécutée en premier

On lit : « Donne-moi les noms des clients qui sont dans la liste des client_id des commandes de plus de 500 €. »

📌 Les 3 règles d'or

  • Une sous-requête est toujours entre parenthèses ( ... )
  • Elle s'exécute avant la requête principale (sauf cas corrélés, voir l'onglet « Types »)
  • Elle peut apparaître dans SELECT, FROM, WHERE ou HAVING
Astuce de lecture : quand vous voyez une requête imbriquée, lisez-la de l'intérieur vers l'extérieur — commencez par la parenthèse la plus profonde !

Les grands types de sous-requêtes

Cliquez sur chaque type pour découvrir sa syntaxe et un exemple commenté sur nos tables.

1. Sous-requête avec IN la plus courante

IN teste si une valeur appartient à la liste renvoyée par la sous-requête. La sous-requête doit retourner une seule colonne.

-- Les clients qui n'ont jamais commandé (NOT IN !)
SELECT nom
FROM clients
WHERE id NOT IN (SELECT client_id FROM commandes);

-- Résultat : Bruno (id 2 est le seul absent des commandes)
2. Sous-requête avec un opérateur de comparaison (=, >, <…)

Quand la sous-requête renvoie une seule valeur (une ligne, une colonne), on peut la comparer directement.

-- Les commandes supérieures à la commande moyenne
SELECT produit, total
FROM commandes
WHERE total > (SELECT AVG(total) FROM commandes);

-- AVG(total) = 320 → gardé : Ordinateur (900), Écran... non (300), Tablette (600)
Attention : si la sous-requête renvoie plusieurs lignes, = provoque une erreur. Utilisez IN, ou ANY/ALL.
3. Sous-requête dans FROM (table dérivée)

Le résultat d'une sous-requête devient une table temporaire que l'on interroge. On doit lui donner un alias (ici stats).

SELECT stats.client_id, stats.total_client
FROM (SELECT client_id, SUM(total) AS total_client
      FROM commandes
      GROUP BY client_id) AS stats
WHERE stats.total_client > 500;

-- stats = table temporaire : | client_id | total_client |
--                        | 1         | 925          |
--                        | 3         | 380          | ...
-- Résultat : client 1 (925) et client 4 (600)

Très pratique dès qu'il faut agréger puis filtrer sur l'agrégat (équivalent de HAVING).

4. Sous-requête corrélée niveau +1

La sous-requête fait référence à la ligne courante de la requête principale : elle est réévaluée pour chaque ligne. On la reconnaît car la table interne mentionne une colonne de la table externe.

-- Les clients dont UNE commande dépasse 500 €
SELECT DISTINCT c.nom
FROM clients c
WHERE 500 < (SELECT MAX(total)
               FROM commandes o
               WHERE o.client_id = c.id);
                -- 👆 c.id : colonne de la requête EXTERNE → corrélée !

Pour chaque client, SQL calcule le max de ses commandes, puis compare à 500.

Performance : les sous-requêtes corrélées peuvent être lentes sur de grosses tables (réévaluées ligne par ligne). Un JOIN ou EXISTS est souvent plus efficace.
5. EXISTS / NOT EXISTS alternative à IN

EXISTS vérifie simplement que la sous-requête renvoie au moins une ligne — peu importe les colonnes.

-- Les clients qui ont au moins une commande
SELECT nom
FROM clients c
WHERE EXISTS (SELECT 1
              FROM commandes o
              WHERE o.client_id = c.id);

-- NOT EXISTS = les clients sans aucune commande → Bruno

SELECT 1 est une convention : on se fiche du contenu, seul « est-ce vide ? » compte. C'est aussi la manière la plus sûre d'écrire « qui n'a jamais… ».

6. Sous-requête dans SELECT (colonne calculée)

Une sous-requête peut produire une colonne du résultat, à condition de renvoyer une seule valeur par ligne.

SELECT c.nom,
       (SELECT COUNT(*) FROM commandes o
        WHERE o.client_id = c.id) AS nb_commandes
FROM clients c;

-- nom    | nb_commandes
-- Alice  | 2
-- Bruno  | 0
-- Chloé  | 2
-- David  | 1

🤔 Sous-requête ou JOIN ?

Beaucoup de sous-requêtes peuvent s'écrire avec un JOIN. Les deux sont corrects ; en général :

  • JOIN : quand on a besoin des colonnes des deux tables dans le résultat
  • Sous-requête : quand on pose une question « ensembliste » (existe-t-il ? est-il dans la liste ? plus grand que la moyenne ?)
  • Sur de grosses tables, EXISTS/JOIN sont souvent plus rapides que IN corrélé

Pièges classiques & conseils

⚠️ Piège 1 : plusieurs colonnes avec IN

-- ❌ Erreur : la sous-requête renvoie 2 colonnes
WHERE id IN (SELECT client_id, total FROM commandes);

-- ✅ Correct : une seule colonne
WHERE id IN (SELECT client_id FROM commandes);

⚠️ Piège 2 : NOT IN et les valeurs NULL

Si la sous-requête contient un NULL, NOT IN ne renvoie… aucune ligne ! (toute comparaison avec NULL est « inconnue »).

-- ❌ Dangereux si client_id peut être NULL
WHERE id NOT IN (SELECT client_id FROM commandes);

-- ✅ Sûr et souvent plus rapide
WHERE NOT EXISTS (SELECT 1 FROM commandes o
              WHERE o.client_id = clients.id);

⚠️ Piège 3 : oublier l'alias avec une table dérivée

-- ❌ Erreur : « every derived table must have its own alias »
FROM (SELECT ... GROUP BY client_id)

-- ✅ Toujours nommer la table temporaire
FROM (SELECT ... GROUP BY client_id) AS stats

💡 Conseils de pro pour bien débuter

  • Testez la sous-requête seule d'abord : exécutez-la, regardez son résultat, puis intégrez-la
  • Lisez de l'intérieur vers l'extérieur : commencez par la parenthèse la plus profonde
  • Indentez vos sous-requêtes — la lisibilité sauve des heures de débogage
  • Une sous-requête peut contenir une autre sous-requête (imbrication multiple), mais au-delà de 2–3 niveaux, préférez des CTE (WITH)
  • Le mot-clé WITH (CTE) permet de nommer une sous-requête et de la rendre lisible : WITH stats AS (SELECT ...) SELECT ... FROM stats

🧭 Récapitulatif express

IN (SELECT ...)          → appartient à une liste (1 colonne)
NOT IN (SELECT ...)      → absent d'une liste (gare au NULL !)
> / = (SELECT ...)        → comparaison (1 seule valeur)
FROM (SELECT ...) AS t   → table dérivée (alias obligatoire)
EXISTS (SELECT ...)       → au moins une ligne ? (souvent corrélée)
SELECT (SELECT ...)       → colonne calculée (1 valeur par ligne)
